# 商铺信息管理系统 \- 数据库初始化说明

本目录为**商铺信息管理系统**数据库初始化资源目录，包含完整数据库建表脚本与初始化说明文档。数据库基于 **MySQL 8\.0** 构建，全局字符集采用 **utf8mb4**，适配中文及 Emoji 符号，共计 11 张业务数据表，全面覆盖商铺、租户、合同、租金、收款、账单、员工、商户账号、历史记录等核心业务场景数据。

## 一、目录内容

|文件名称|文件说明|
|---|---|
|init\.sql|完整建表语句 \+ 基础初始测试数据，支持一键初始化完整数据库|
|README\.md|数据库部署、初始化、表结构、使用注意事项说明文档（本文档）|

## 二、快速开始

以下为数据库快速初始化部署步骤，全程适配命令行及主流数据库可视化工具。

### 1\. 创建数据库

登录 MySQL 服务端后，执行以下 SQL 创建专属数据库，指定字符集及排序规则：

```sql
CREATE DATABASE IF NOT EXISTS shop_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 2\. 执行初始化脚本

方式一：命令行执行（推荐）

```bash
mysql -u root -p shop_db < init.sql
```

方式二：可视化工具执行
使用 DataGrip、Navicat、DBeaver 等工具打开 `init.sql` 文件，选中全部语句执行即可完成初始化。

### 3\. 验证初始化结果

执行以下校验 SQL，确认数据库表结构及初始数据正常写入：

```sql
USE shop_db;

-- 查看所有数据表
SHOW TABLES;

-- 验证商铺初始数据（预期15条）
SELECT COUNT(*) FROM shop;

-- 验证员工初始数据（预期4条）

-- 验证商场布局配置（预期1条）
```

## 三、数据表结构总览

|序号|表名|业务说明|
|---|---|---|
|1|boss\_config|老板配置表，存储后台超级管理员账号、加密密码等核心配置|
|2|mall\_layout|商场布局配置表，记录商场总层数、每层商铺数量等全局布局信息|
|3|shop|商铺信息表，存储铺位号、商铺面积、出租状态、所属租户等商铺基础数据|
|4|tenant|租户信息表，存储租户姓名、身份证号、经营品牌、联系方式等租户资料|
|5|contract|合同信息表，存储合同编号、租赁起止日期、审核状态、关联商铺及租户信息|
|6|rent|租金方案表，记录租金计费模式（固定/抽成）、单价、缴费周期等规则|
|7|receipt|收款单表，记录每期租金应收金额、实收金额、欠收金额、催收状态等收款数据|
|8|bill|商户账单表，面向租户展示的正式账单数据，与收款单一一对应|
|9|shop\_history\_tenant|商铺历史租户表，用于退租后归档历史租赁、租户、合同数据，留存记录|
|10|employee|员工信息表，存储员工工号、所属部门、岗位职级、登录账号密码等信息|
|11|merchant\_account|商户账号表，存储租户前台登录用户名、加密密码，关联对应租户信息|

## 四、实体关系（ER）说明

### 4\.1 核心实体关联关系

```Plain Text
shop (1) ─────< (n) contract
tenant (1) ───< (n) contract
contract (1) ── (1) rent
contract (1) ──< (n) receipt
receipt (1) ─── (1) bill
tenant (1) ──── (1) merchant_account
shop (1) ─────< (n) shop_history_tenant
tenant (1) ───< (n) shop_history_tenant
contract (1) ── (1) shop_history_tenant
```

### 4\.2 关系详细说明

- 一个商铺可关联多条历史合同，同一时间仅存在一条有效合同，通过 `shop.is_rented` 字段标识出租状态

- 一个租户可签订多份租赁合同，可同时租赁多个商铺

- 每份有效合同唯一对应一套租金计费方案

- 一份合同可按周期（月/季）生成多期收款单

- 每一张收款单唯一对应一张商户可视化账单，用于推送展示

- 一个租户对应一个专属商户登录账号

- 租户退租后，对应商铺、租户、合同数据自动归档至历史租户表，用于数据溯源

## 六、部署与使用注意事项

### 6\.1 bcrypt 密码哈希重置（重要）

init\.sql 中内置的加密密码为示例哈希值，由于 bcrypt 算法特性，相同明文每次生成的哈希值均不同。**生产环境务必重新生成哈希并替换**。

Python 重置密码哈希代码：

```python
from passlib.context import CryptContext

pwd = CryptContext(schemes=["bcrypt"], deprecated="auto")
# 生成明文123456的加密哈希
print(pwd.hash("123456"))
```

执行后将输出的新哈希值，批量替换脚本中老板、员工、商户的所有 password 字段。

### 6\.2 自动生成列说明

`receipt.unpaid_amount`、`bill.unpaid_amount` 为 MySQL 计算生成列，计算公式：`未付金额 = 应收金额 - 实收金额`。

该字段由数据库自动计算，**新增、修改数据时禁止手动赋值**，否则会报错。

### 6\.3 外键约束说明

各业务表存在依赖外键关系，脚本已提前排序，直接完整执行即可。若需手动清空数据、批量修改数据，需临时关闭外键检查：

```sql
-- 关闭外键检查
SET FOREIGN_KEY_CHECKS = 0;

-- 执行数据删除/清空操作

-- 恢复外键检查
SET FOREIGN_KEY_CHECKS = 1;
```

### 6\.4 脚本重复执行说明

脚本内包含 `DROP TABLE IF EXISTS` 逻辑，支持重复执行初始化，但**重复执行会清空所有业务数据并重置为初始测试数据**，生产环境谨慎操作。

### 6\.5 字符集规范

全库、全表统一使用 **utf8mb4** 字符集，完整支持中文、特殊符号、Emoji 表情，无乱码风险。

## 七、常用运维 SQL 语句

```sql
-- 1. 查询指定租户的所有合同记录
SELECT * FROM contract WHERE tenant_id = 1;

-- 2. 查询指定合同的租金计费方案
SELECT * FROM rent WHERE contract_id = 1;

-- 3. 查询指定租户的全部商户账单
SELECT * FROM bill WHERE tenant_id = 1;

-- 4. 查询所有历史退租归档记录
SELECT * FROM shop_history_tenant;

-- 5. 查看所有商铺出租状态及当前租户
SELECT id, shop_number, is_rented, current_tenant_id FROM shop;
```
